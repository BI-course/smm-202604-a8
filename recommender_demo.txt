What works
POST /api/v1/models/ecommerce-recommender/predictions
Loads model/apriori_recommendation_rules.joblib once at startup.
Uses the existing association rules; no training or rule mining in api.py.
Returns product names, SKUs, confidence and lift.
Validates missing/empty carts, invalid SKU types, unknown SKUs and top_n.

The page is frontend/ecommerce_recommender.html.
It shows clear errors for missing input, invalid counts, unknown products,
connection failures and API errors. Blank/comma-only input sends no request.
An editable API address supports local Flask and deployed API servers.

Artifact compatibility fix
The original saved file used a pandas string dtype that failed to deserialize
under the repository's pinned pandas 2.2.3. The same data was exported through
an isolated pandas environment and re-saved using pandas 2.2.3. All 56 rules,
the complete recommendation lookup, all 35 product records and their scores
were compared and preserved exactly. The model was never retrained.
The original binary backup is outside the repository at
../.artifact-inspection/original_apriori_recommendation_rules.joblib.
The API uses the normal pinned environment and needs no inspection packages.

API behavior
Request: {"cart": ["H06", "H07"], "top_n": 3}
Every rule's full antecedent must be in the cart to match.
Products already in the cart are excluded. Duplicate recommendations are
ranked by confidence, then lift, then SKU for stable ties.
top_n defaults to 3 and accepts integers from 1 to 20.
Known carts with no eligible recommendations return HTTP 200 and an empty list.
Invalid inputs return HTTP 400 with a JSON error message.
